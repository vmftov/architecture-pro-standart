|-----|--------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| F   | **Функциональные (Functionality)**                                                                           |                                                                                                              |
| F1  | Список доступных депозитов на сайте должен быть виден и текущим, и новым/незарегистрированным клиентам       | Архитектурно-значимое, т.к. потребует более серьезного контроля безопасности (например, меры против мошенников и DDOS), а также маршрутизации на новые сервисы (API Gateway) |
| F3  | Менеджер кол-центра должен видеть заявку на депозит, оставленную новым клиентом на сайте                     | Архитектурно-значимое, т.к. влияет на характер взаимодействия разных систем                                  |
| F10 | Сотрудники бэк-офиса депозитов и бэк-офиса кредитов должны работать со ставками по депозитам в рамках АБС    | Архитектурно-значимое, т.к. влияет на используемое ПО и взаимодействие с текущими системами                  |
| F11 | На сайте новый клиент видит предложение открыть кредит по некоторой ставке                                   | Архитектурно-значимое, аналогично F1                                                                         |
| F15 | Сотрудник офиса должен иметь доступ и возможность работать с предварительно одобренной заявкой на кредит     | Архитектурно-значимое, т.к. потребует добавления механизма синхронизации между АБС и новым микросервисом     |
| R   | **Надёжность (Reliability)**                                                                                 |                                                                                                              |
| R1  | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев                                             | Архитектурно-значимое, т.к. потребует добавления новых сервисов т.к. текущая БД системы уже перегружена      |
| R2  | Интернет-банк должны работать 24/7 и быть доступны в 99,9% случаев                                           | Архитектурно-значимое, т.к. сейчас имеются непреодолимые ограничения, что потребует переработки интернет-банка, м.б. добавления дублера на новых технологиях |
| P   | **Производительность (Performance)**                                                                         |                                                                                                              |
| P1  | Отклик по всем операциям должен занимать миллисекунды                                                        | Архитектурно-значимое, т.к. потребует добавления кэша или переработку логики работы со справочниками         |
| P2  | Заявки на кредит по предодобренным предложениям должны обрабатываться в течение того же рабочего дня         | Архитектурно-значимое, т.к. потребует пересмотра взаимодействия АБС и скоринга, м.б. добавления новых сервисов |
| +R  | **+ Ограничения (Restrictions)**                                                                             |                                                                                                              |
| +R1 | Необходимо использовать, по возможности, только СУБД MS SQL и Oracle                                         | Архитектурно-значимое, т.к. ограничивает применение новых технологий                                         |
| +R2 | Новые технологии, должны быть совместимы с существующими платформами разработки                              | Архитектурно-значимое, т.к. ограничивает применение новых технологий                                         |
| +R4 | В качестве очереди сообщений рекомендуется использовать Kafka                                                | Архитектурно-значимое, т.к. интернет-банк несовместим с ней и потребуется написание адаптера                 |
| +R5 | Рекомендуется перевести интернет-банк на микросервисную архитектуру                                          | Архитектурно-значимое, т.к. потребует разбиения текущих систем на сервисы и менять характер взаимодействия   |
| +R6 | Требуется обеспечить равномерное горизонтальное масштабирование запросов между серверами, приложениями и ЦОД | АБС может масштабироваться только вертикально из-за своей базы данных                                        |
| +R7 | Трафик при работе с сайтом и интернет-банком необходимо защищать с помощью механизма шифрования              | Архитектурно-значимое, т.к. потребует пересмотра и контроля логики передачи данных, м.б. добавления Gateway  |
| +R8 | Рекомендуется реализовать функционал работы с СМС силами команды банка                                       | Архитектурно-значимое, т.к. потребует выделения нового сервиса работы с СМС из АБС (по Strangler Fig)        |
| +R10| Запрещено нагружать систему кредитного скоринга дополнительными процессами по предрасчетам скорингов         | Архитектурно-значимое, т.к. потребуется разработка доп сервисов для расчета скоринга новых клиентов          |
